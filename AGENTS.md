# mimose

A browser app built with plain HTML, CSS and JavaScript. It uses ES modules and
has no framework, no bundler and no build step.

## Tech stack

- HTML5, CSS and JavaScript (ES modules).
- No framework and no build step. Keep the app runnable by serving the project
  directory with any static file server.
- Prefer browser APIs over third-party libraries. Add a dependency only when it
  clearly earns its place.

## Writing code

- Use ES modules: `import` / `export` in `.js` files and
  `<script type="module" src="...">` in HTML.
- Keep HTML semantic. Label form controls, preserve keyboard navigation and
  meet WCAG AA contrast.
- Keep JavaScript, CSS and markup in separate files. No inline event handlers
  and no inline styles.
- Define colors, spacing, radius and typography as CSS custom properties on
  `:root`, and consume the tokens instead of hardcoding values.
- Organize code by feature. One responsibility per module; export only what
  other modules need.
- Use `const` and `let`, never `var`. Prefer small, pure functions. Name things
  by what they do.
- Handle errors explicitly. Show a useful state in the UI; never fail silently.
- Comments explain why, not what. Avoid comments that restate the code.
- Do not commit generated files, secrets or local environment files.
- Run the app in a browser before declaring a task done.

## Language rules

- All code, identifiers, comments, commit messages, UI labels and user-facing
  strings MUST be written in English.
- Keep commit messages short and follow Conventional Commits
  (`feat: ...`, `fix: ...`, `refactor: ...`, `chore: ...`).

## Committing and pushing

- Use short, imperative commit messages in English with a Conventional Commits
  prefix:
  - `feat: short message` - a new feature.
  - `fix: short message` - a bug fix.
  - `refactor: short message` - a change that neither adds a feature nor fixes a bug.
  - `chore: short message` - maintenance that does not change behavior.
- Never add AI authorship or co-author trailers (no `Co-Authored-By`, no
  "Generated by ...", no tool/agent attribution). The commit author is the
  human contributor only.
- Stage only the intended files, then commit to the current branch.

```bash
git add <files>
git commit -m "feat: short message"
```

## Releases

- Use Semantic Versioning and tag releases as `vX.Y.Z`. Pre-releases use a
  suffix such as `vX.Y.Z-alpha.1`.
- Release commits use `chore(release): vX.Y.Z`.
- Write release notes with [docs/RELEASE_TEMPLATE.md](docs/RELEASE_TEMPLATE.md),
  grouping changes since the previous tag by type: features, fixes,
  refactor/chore/docs, and other.
- Describe user-visible changes. Do not list commits that are not shipped.
- Publish the release on GitHub with the generated notes. Mark versions with a
  pre-release suffix as pre-releases.
- Do not move or delete an existing release tag. Fix the problem with a new
  patch release.
